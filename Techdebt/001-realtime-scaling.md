# 001. Realtime при масштабировании

`PgListenerService.lastId` хранится in-memory в каждом инстансе API.

При одном инстансе это корректно. При двух и более инстансах (blue-green, rolling update, горизонтальное масштабирование) возможны пропуски или дубли SSE-событий при переключении фронта между инстансами.

Возможные решения:

1. Sticky sessions на балансировщике.
2. Вынести курсор в БД (`sync_cursor` + `SELECT ... FOR UPDATE`).
3. Отдельный сервис-раздатчик SSE.

Решать в момент, когда появляется второй инстанс API. Не раньше.

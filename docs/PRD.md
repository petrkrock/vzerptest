# PRD — ВСЕМЗАПЧАСТИ CRM (vzcrm)

> Продуктовое описание «как есть» (as-built). Источник истины — код и `supabase/schema.sql`.
> История изменений — в `MIGRATION.md`, регламент работы — в `WORKFLOW.md`.

## 1. Назначение

CRM-платформа для управления экосистемой B2B-автозапчастей: поставщики, покупатели,
лиды, задачи, поддержка, медиа-размещения, проценка (DBS), план/факт,
аналитика и база знаний. Веб-приложение SPA + PWA: десктоп, планшет, мобильный.
Интерфейс — русскоязычный.

## 2. Пользователи и роли

| Роль | Возможности |
|---|---|
| **Администратор** | Полный доступ: главный дашборд, аналитика, настройки (пользователи, справочники, статусы, формы, ЛК), база данных (логи), серверный мониторинг, предпросмотр дашбордов менеджеров. |
| **Менеджер (МОП)** | Дашборд МОП (продажи/покупатели), покупатели в закреплённых городах, задачи, поддержка, база лидов (покупатели), база знаний, План/Факт (база «покупатели», read-only). |
| **Менеджер (МОЗ)** | Дашборд МОЗ (закупки/поставщики), поставщики, медиа сервис, задачи, поддержка, база лидов (поставщики), база знаний, План/Факт (база «поставщики», read-only). |

- Модель видимости менеджера: **свои записи + записи без ответственного**.
- Доступ к разделам — галочками в профиле пользователя (`AppUser.permissions`).
- Уточняющие фильтры (`UserAccess`): типы/города поставщиков и покупателей, типы
  тикетов, города планов, фильтры дашборда/задач/медиа/аналитики/знаний.
  Пустой массив = без ограничений.
- Учётные записи: статусы `active` / `blocked` / `fired` (уволен — доступа нет).
- Тип дашборда (`dashboardType: mop|moz`), база План/Факт (`planfactBase`) и база
  лидов (`leadsBase`) менеджера фиксируются администратором.

## 3. Разделы (навигация)

- **Работа**: Дашборд (общий/МОП/МОЗ), План/Факт, Поставщики, Покупатели, Задачи,
  Поддержка, База лидов.
- **Сервисы**: Медиа сервис, Проценка (DBS), Аналитика, База знаний.
- **Система** (только админ): Настройки, База данных (логи, логи дублей, логи синка,
  экспорт CSV, бэкап), Сервер (мониторинг).

## 4. Ключевые сущности

| Сущность | Хранение | Назначение |
|---|---|---|
| Supplier (поставщик) | таблица `suppliers` | Карточка поставщика: реквизиты, склады, скоринг, категория A/B/C, ЭДО, сервис поиска, доступы в ЛК. |
| Buyer (покупатель) | таблица `buyers` | Карточка покупателя: реквизиты, скоринг, категория A/B/C. |
| Lead (лид) | `app_settings.leads` (JSONB) | База лидов поставщиков/покупателей: импорт CSV, архив, дедупликация. |
| Task (задача) | таблица `tasks` | Задачи по сущностям, приоритет, история, мягкое удаление (журнал). |
| Ticket (обращение) | таблица `tickets` | Поддержка: типы/категории/приоритеты, конвертация в задачу. |
| MediaRecord | таблица `media_records` | Медиа-размещения: форматы, тарифы, длительности, статусы. |
| PlanFactEntry | `app_settings.planFact` | Планы по покупателям/поставщикам: период, город/сервисы, план, отчёт, история. |
| KnowledgeItem | `app_settings.knowledgeItems` + Storage `knowledge` | База знаний: файлы, ссылки, заметки, комментарии. |
| AppUser | `app_settings.users` | Пользователи CRM, права, фильтры, уведомления. |
| MarketVolumeRecord | `app_settings.marketVolumes` | Снимки объёма рынка (аналитика). |

## 5. Внешние интеграции и публичные поверхности

- **Supabase**: PostgreSQL + Auth (JWT) + Edge Functions + Storage — весь бэкенд.
- **Checko API**: автоматический скоринг по ИНН (ключ в настройках, edge function `checko`).
- **Уведомления о заявках**: Telegram / MAX / email — через edge function `public-form`
  (токены только в Supabase Secrets).
- **Публичная форма заявок**: настраиваемые формы (поставщик/покупатель/обращение/
  маркетинг-кит) с consent-галочкой, rate limit и honeypot.
- **ЛК поставщика (сервис поиска)**: `/s/<token>` — поставщик сам заполняет склады и
  условия; изменения прилетают в CRM со статусами «Новое/Загружено/Есть изменения».
- **Экспортные ссылки**: `/entity-export/:taskId`, `/leads-export/:taskId` — файлы
  выгрузок, приложенные к задачам.
- **Платформа vsemzapchasti.ru** (план, v1.31.0): интеграция чата платформы в ЛК
  (VZ Чат) и чат поддержки CRM↔ЛК.

## 6. Продуктовые инварианты

1. **Мягкое удаление** везде: `deletedAt` вместо физического удаления; удаление
   задач/записей фиксируется в журнале (`app_logs`, вкладка «Логи»).
2. **История изменений** у поставщиков, покупателей, задач, тикетов, планов,
   маршрутов — кто/когда/что поменял.
3. **Системные статусы** (поставщики/покупатели/лиды/задачи/тикеты/медиа) создаются
   автоматически при загрузке (`ensureSystemStatuses`), удалению не подлежат.
4. **Права менеджеров** хранятся в профиле в `app_settings` — миграции БД под права
   не нужны.
5. **Service-role ключ** никогда не попадает в браузер — только серверный
   `monitor-server.js`.
6. **Демо-режим** (`VITE_DEMO_MODE=true`): синхронизация отключена, данные только
   в localStorage (вход `admin@admin.com` / `admin123`).
